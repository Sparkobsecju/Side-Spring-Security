# 註解與文件規範

只在修改 Java、HTML、XML、規格或既有註解時載入本文件。

## 通用原則

- 使用繁體中文說明設計意圖、必要契約、安全取捨與非直覺行為。
- 優先解釋「為什麼」，避免逐行重述可直接從語法看出的內容。
- 行為改變時同步更新或移除過時註解，不得讓註解、規格與實作互相矛盾。
- 規格文件應記錄責任邊界、輸入輸出、主要流程、限制、擴充原則及驗收條件。

## 依檔案類型

### Java

- 新增或修改類別時，為類別與公開方法補上 Javadoc。
- Javadoc 應描述責任、參數、回傳值、例外及重要生命週期，不需要重述實作細節。
- Security 程式必須說明公開路徑、登入／登出端點、轉址行為及安全取捨。

### HTML

- 說明頁面對應路由、表單提交端點，以及與 Spring Security 或 Thymeleaf 的整合條件。
- 不為純樣式或語意已明確的標籤加入無資訊價值的註解。

### `pom.xml`

- 新增或修改 dependency、plugin 或重要 property 時，以 XML 註解說明用途與 scope。
- 版本由 Spring Boot Parent 管理時，註明不另外鎖版的原因；只有必要時才覆寫版本。

### Markdown 規格

- 檔名應直接反映套件或功能用途，不使用無法辨識範圍的泛用名稱。
- 以相對連結連接同一專案內的延伸規格，避免重複維護相同內容。
- 修改程式契約時，必須檢查相關規格與 `AGENTS.md` 的按需索引是否仍正確。
